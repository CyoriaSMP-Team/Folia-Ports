# Migration compatibility checklist

Current target: Minecraft 1.21.11, Folia build 14, Java 25.

CyoriaSMP has switched engine. Unsupported historical plugin JARs and their configuration data are retained in a backup or quarantine outside the plugin loading path. This is a staged feature migration, not full plugin parity.

## Priority blockers

1. Authentication: the official AuthMe 6.0.1 Folia JAR enables, and FastLoginPlus recognizes its AuthMe hook. Startup also reports offline mode and direct connections. Password, premium UUID, proxy, and Java/Bedrock login flows still need a controlled real-client check.
2. World management: MoreFoWorld 1.13.3 loads the existing lobby via server internals; the four worlds and 19 lobby FancyNpcs were listed after cold boot. A live `/mv create ps-folia-smoke normal` attempt still throws `UnsupportedOperationException` from Bukkit.createWorld on Folia. The live Terralith 2.6.0 pack also fails to compile its `setup` and `rtp_testing` functions because Folia rejects the `scoreboard` and `spreadplayers` commands. Keep those helpers disabled; do not restore global scoreboard or cross-region teleport commands without a Folia-safe implementation. Dynamic world creation, RTP, portals, player teleports, and other world lifecycle flows remain unverified.
3. Region claims: ProtectionStones `v2.10.7-folia.1` starts on live Folia and passed isolated 25x25 claim creation, visitor protection, and owner unclaim. Multi-region and cross-region world changes remain unverified; treat the port as experimental.
4. Economy: ExcellentEconomy, ExcellentCrates, ExcellentEnchants, tokens, and rewards need compatible builds with data integrity.
5. Custom core: CyoriaCore's private Folia port now builds and passes a live startup smoke test; its player commands and gameplay paths remain untested. CyoriaInteractiveChat `v0.1.5-folia.1` is published and enabled after live Folia startup; its inline chat and GUI flow passed on isolated Leaf Canary, while live Folia player interaction remains unverified. CyoriaCycRuntime, AuthEyeLab, TPA, and status modules still need direct port or runtime verification.
6. Skript ecosystem: scripts and addons are not assumed compatible; port scripts into Java/CyoriaRuntime or an audited DSL.
7. GUI and gameplay: DeluxeMenus, DecentHolograms, third-party mini-games, and pet systems need test or port.
8. MOTD: `CyoriaMOTDGuard` `v1.0.2-folia.1` is published and loads without BannerMOTDplus because Banner is now an optional dependency. Java protocol 774 and a RakNet pong passed live checks; the guard observed Geyser protocol 776. One status client still produced `Status client channel unavailable`, so version routing for that client is not confirmed. The official BannerMOTDPlus 2.0.0 JAR is staged but lacks Folia's required `folia-supported: true` marker; Modrinth lists Paper, Purpur, BungeeCord, and Velocity and marks it ARR. Do not patch or publish a modified copy without maintainer permission. MiniMOTD remains the working response while Banner is absent.

Only install an artifact from a passing workflow after confirming plugin.yml explicitly supports Folia and running runtime smoke tests; folia-supported: true alone is insufficient.
